# Implementation and verification

This PR delivers the inventory, policy design and proposed requirement. Keep #11 open for implementation and evidence. No live AWS account is required for PR review.

## Reviewable implementation

- [ ] **Build and test the policy generator.** Translate the [inventory](inventory.md) into IAM statements, documenting each caller, resource type and wildcard exception. Cover maximum-length and overlapping environment names, both ownership tags, existing/absent resources, tag changes, multi-resource operations, DNS batches containing both allowed and disallowed names, cross-region access and the actual provider lock. Exercise indirect authorization through a host with an overly broad inline policy. Check first creation, restore, and retirement of a master ARN with both supported boundary designs. Test document/attachment size limits and service-linked role prerequisites.
- [ ] **Integrate operator bootstrap and migration.** Cover fresh, repeated and interrupted bootstrap, stale policy versions, missing tags, a renamed DNS record, unknown broad grants, failure before/after detaching the legacy policy and retry. Assert the existing conditioned IAM policy and PR plan role remain equivalent. Retain existing deployments' role ARNs. Update the AWS guide, generated runbook, security limitation and changelog to identify the bootstrap needed for adoption, hostname changes and first use or restore of a database under an exact-ARN boundary. Report the command before applying a plan with unauthorized records and document any remaining account-wide reads.
- [ ] **Prove the lifecycle.** Run focused bootstrap and generated-workflow tests, Terraform validate/test with mocked providers, and the offline unit tier. After explicit approval of a named AWS sandbox and changes, run the checks below. Reconcile any change from #9 before final acceptance. [AWS setup/runtime design](https://github.com/vecten/vecten-open/pull/149)

## Live release evidence

Use a dedicated sandbox account, two disposable environments with names sharing a prefix, and known synthetic sibling resources. Set `components = ["platform", "mcp"]` in the primary environment tfvars to exercise both Airflow and the Vecten warehouse server. Record the release commit, provider version, caller role, effective policy version, expected and observed outcome and AWS error code. Exclude credential values, full session responses, state contents and database passwords. Each CI proof uses the actual environment OIDC role after removing PowerUserAccess.

| Stage | Positive evidence | Boundary or recovery evidence |
| --- | --- | --- |
| Bootstrap | On a fresh environment only scoped grants are installed. Migrate an existing role and rerun bootstrap with the same result. Use a fresh OIDC session and verify attachments. | Record pre-existing out-of-band policies. Inject an interruption between installing the scoped grant and removing the old attachment. A retry must converge and report whether broad access remains. |
| First deploy | Run the generated plan and apply. Verify backend locks release, the outputs object is present, RDS has an active managed master, hosts receive the first bundle and endpoints pass health checks. Also exercise `warehouse = "snowflake"` with the platform enabled. Verify the CI session reads DEPLOY_SNOWFLAKE_USER and DEPLOY_SNOWFLAKE_PRIVATE_KEY, initializes or reuses SNOWFLAKE_LOADER_PRIVATE_KEY and releases the Snowflake state lock. | Simulator cases and authorized sandbox probes deny sibling state/secret reads and bundle writes, removal or reassignment of ownership tags, writes to a sibling DNS record, commands to a sibling instance and changes to CI IAM. Confirm the sentinel objects or records exist before testing. |
| Host permissions boundary | Under an operator-approved synthetic fixture, give the test host an inline policy requesting access to both environments. Verify its effective session still permits the intended own-environment master read. Record outcomes only, without retrieving credential values into logs. | Verify the same effective host session is denied a read of the sibling master and a write to the sibling log group, and the CI role cannot change the boundary. Use the same case after restore to check the new and retired master ARNs. |
| Content ship and rollback | A second commit uses existing infrastructure, uploads only host bundles and reports healthy deployment. After a deliberately unhealthy disposable release triggers rollback over SSM, verify the host's current release points to the previous good commit and its component health endpoints recover. | Verify deployment logs are obtained by the traced SSM calls. An unrelated SSM document or instance remains denied. The plan role cannot send commands or read secrets. |
| Tier change and host replacement | Record the Terraform plan for the tier change. If it updates the instance in place, exercise a separately authorized replacement in the sandbox. Verify the new host can receive the bundle and old resources are released. | Verify ownership tags on the new host, volume and interface. The same deploy session cannot change a sibling host or attach its network resources. |
| Snapshot restore | Follow the generated operator runbook to restore, rename, enable a managed master and import the new instance. Run CI deploy and ship against the restored database. Verify a known test record survived. | Record the new DB resource ID and master ARN, and verify application health. The CI result must come from the scoped role. An operator's successful restore does not establish that result. |
| Destroy and retention | Run the approved operator destroy. Verify final snapshots become available, the artifacts bucket including old versions is removed, outputs are cleared, state storage and Vecten secrets remain. | Compare sibling instance IDs, DNS, state, data and secret metadata before and after. Record which deletion actions were operator-only and which were needed by CI during replacement. |

Collect the relevant AWS request and denial metadata for each stage. CloudTrail management history alone omits S3 object data events. If existing evidence cannot identify a call, arrange appropriate sandbox audit coverage before the run. Reproduce a missing permission on the affected step and review its resource and condition scope before extending the allow-list. Record any unverified path explicitly.
