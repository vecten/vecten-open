# AWS deploy permissions inventory

The question for each permission is which identity makes the AWS request. Running Terraform, uploading a bundle and running SQL inside a VM are three different operations. This inventory traces `release/0.1.2` at `90a4c33`, with the AWS provider locked at 6.69.1. It identifies candidate grants from source. The [live checks](tasks.md) determine the effective grants before release. [Provider lock](../../../../terraform/aws/.terraform.lock.hcl) · [AWS provider source at the locked version](https://github.com/hashicorp/terraform-provider-aws/tree/v6.69.1/internal/service)

## Who acts during a full cycle?

| Stage | Caller and evidence to collect |
| --- | --- |
| Bootstrap | The operator's AWS login creates or reconciles the private state bucket, GitHub OIDC provider, host permissions boundary, deploy role and plan role. GitHub exchanges the environment-authorized job's OIDC token for a session of that deploy role. Record the role ARN and attached policy ARNs before and after reconciliation. [Bootstrap](../../../../packages/vecten/src/vecten/deploy/aws/bootstrap.py) |
| PR plan | The plan role reads infrastructure and state and writes only state locks. Its OIDC subjects and policy are separate. Include a plan regression check. [Role construction](../../../../packages/vecten/src/vecten/deploy/aws/bootstrap.py) |
| First deploy | The operator dispatches a GitHub environment job. The job plans and applies the cloud root and optional Snowflake root, writes the environment outputs to S3, then ships. Its AWS calls determine the deploy role's permissions. Record the caller for the apply and for each downstream step. [AWS control plane](../../../../packages/vecten/src/vecten/deploy/aws/__init__.py) · [Snowflake root](../../../../packages/vecten/src/vecten/deploy/snowflake.py) |
| Content ship and failed-health rollback | The deploy role reads the saved outputs, lists a host's bundle prefix, uploads a tarball, calls Systems Manager (SSM) Run Command and polls its result. Health polling uses HTTPS. The host's EC2 profile downloads the bundle and the host agent reads setup secrets and runs SQL. Rollback sends a second command to the same host. [Ship](../../../../packages/vecten/src/vecten/deploy/aws/ship.py) |
| Tier change or replacement | The deploy role refreshes and changes resources through Terraform, then ships again using the new instance IDs. Record the plan and IDs. A stop/modify/start of the same instance exercises a different set of permissions than replacement. Exercise both where supported, including deletion of the previous host. [Host](../../../../terraform/aws/modules/host/main.tf) · [Database](../../../../terraform/aws/modules/postgres/main.tf) |
| Restore and adoption | The operator restores a snapshot to a temporary identifier, verifies data, renames the instances, enables the RDS-managed master and imports the restored instance into state. The next deploy job must refresh and apply the adopted resource, update the host policy with its new master ARN and ship. Direct restore, state surgery, opening an SSM admin tunnel and deleting the retired DB are operator work. [Generated runbook source](../../../../packages/vecten/src/vecten/scaffold/template/docs/runbook.md.jinja) |
| Destroy | The CLI normally runs under the operator's laptop login. It creates and waits for final DB snapshots, lifts protection, empties the versioned artifacts bucket through Terraform, destroys the resources and removes the saved outputs. It keeps state storage and Vecten secrets. Record this caller distinctly from the deploy role's resource deletion during ordinary apply/replacement. [Snapshot calls](../../../../packages/vecten/src/vecten/deploy/aws/snapshots.py) · [AWS control plane](../../../../packages/vecten/src/vecten/deploy/aws/__init__.py) |

## Candidate deploy-role grants

Use the exact configured account and region for regional ARNs. The rendered provider tags resources with `vecten:project` and `vecten:env`. The computed name prefix is truncated and normalized. Names alone cannot establish ownership when one environment name extends another. Use the repository's naming functions for exact resource names. Below, “owned” means the expected resource identity and both ownership tags wherever AWS supports them for that action. [Name derivation](../../../../packages/vecten/src/vecten/deploy/names.py) · [Generated provider and tags](../../../../packages/vecten/src/vecten/scaffold/template/%5B%25%20if%20render_deploy%20%25%5Ddeploy%5B%25%20endif%20%25%5D/terraform/%5B%5B%20cloud%20%5D%5D/main.tf.jinja)

| Service and call site | Candidate actions and scope |
| --- | --- |
| EC2 network | For the VPC, internet gateway, subnets, route table, its associations and security groups, cover create, describe, update, delete and tagging. Include `ModifyVpcAttribute`, `ModifySubnetAttribute`, gateway attach/detach, `CreateRoute`, `ReplaceRoute`, `DeleteRoute`, route table associate/replace/disassociate, security group ingress/egress authorize/revoke and `ModifySecurityGroupRules`. Separate permissions to create a tagged child from permissions on its already-owned parent. Check both resources for operations with two endpoints. Refresh reads include availability zones, the VPC's default ACL, default security group and main route table. [Network resources](../../../../terraform/aws/network.tf) · [Provider VPC read](https://github.com/hashicorp/terraform-provider-aws/blob/v6.69.1/internal/service/ec2/vpc_.go) |
| EC2 compute and storage | Create/delete the tagged network interface, allocate/associate/disassociate/release its Elastic IP, launch/terminate the tagged instance and encrypted root volume, start/stop and modify instance attributes, modify metadata options and grow the volume. Account for tag-on-create, reads of AMIs, instance types, profile associations, network interfaces, addresses, volume attributes and modification status. For `RunInstances`, distinguish the Amazon image input, existing owned network resources and newly tagged instance/volume. Constrain the passed profile using the existing IAM rules. Verify root-volume ownership tags at launch and upgrade. [Host module](../../../../terraform/aws/modules/host/main.tf) · [Provider instance paths](https://github.com/hashicorp/terraform-provider-aws/blob/v6.69.1/internal/service/ec2/ec2_instance.go) |
| RDS | Provision and refresh the exact `<prefix>-state` and optional `<prefix>-warehouse` database and subnet groups, and their `-pg17` parameter groups. Cover CreateDBInstance, DescribeDBInstances, ModifyDBInstance and DeleteDBInstance. Include create/modify/delete for DB subnet and parameter groups, DescribeDBSubnetGroups, DescribeDBParameterGroups, DescribeDBParameters, ResetDBParameterGroup, ListTagsForResource, AddTagsToResource and RemoveTagsFromResource. Review any reboot issued for this configuration. Restrict types separately using `db:`, `subgrp:` and `pg:` ARNs. A restored instance has a new resource ID even after rename. Snapshot creation/wait, restore and temporary `-restored` / `-old` names belong to the operator procedure above. [RDS resources](../../../../terraform/aws/modules/postgres/main.tf) · [Provider](https://github.com/hashicorp/terraform-provider-aws/tree/v6.69.1/internal/service/rds) |
| S3 state backend | Read/write the state bucket objects `<env>/aws.tfstate`, optional `<env>/snowflake.tfstate`, and `<env>/outputs.json`. Get, put and delete the matching `.tflock` for each Terraform root. Limit bucket listing to backend needs, testing Terraform's workspace discovery on init. State bucket creation, encryption, versioning and TLS policy belong to operator bootstrap. Terraform's lock release does not require deletion of the state object. [Backend keys](../../../../packages/vecten/src/vecten/deploy/terraform.py) · [S3 backend permissions](https://developer.hashicorp.com/terraform/language/backend/s3) |
| S3 artifacts | Manage the one exact artifacts bucket, its public-access block, versioning, AES256 encryption, lifecycle and tags. Use IAM names such as `s3:PutEncryptionConfiguration`, `s3:PutLifecycleConfiguration` and `s3:PutBucketPublicAccessBlock`. Refresh in 6.69.1 reads additional configuration, including policy, ACL, logging, website, CORS, replication, acceleration, request payment and object-lock settings. Inspect tag-on-create (`s3:TagResource`) and provider fallback. Ship uses `s3:ListBucket` and `s3:PutObject` under `bundles/<host>/`. Host downloads, Airflow log writes and deleting all versions and delete markers on forced teardown have different callers. [Bucket](../../../../terraform/aws/bucket.tf) · [Provider bucket read](https://github.com/hashicorp/terraform-provider-aws/blob/v6.69.1/internal/service/s3/bucket.go) |
| Route 53 | Resolve the selected public zone at bootstrap. Terraform currently calls `ListHostedZones`, then reads the selected zone, tags, records and change status. Give `ChangeResourceRecordSets` on the exact hosted-zone ARN. Use `ForAllValues:StringEquals` on the Route 53 normalized record names, record types (A only) and actions (CREATE/UPSERT/DELETE). Require those context keys to be present so an empty set cannot satisfy the batch check. Derive names from the enabled components and bound extension hostnames, including an allowed environment apex. Include removal of old records in a configuration change. [DNS resources](../../../../terraform/aws/dns.tf) · [Provider zone lookup](https://github.com/hashicorp/terraform-provider-aws/blob/v6.69.1/internal/service/route53/zone_data_source.go) · [Route 53 conditions](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/specifying-conditions-route53.html) |
| Secrets Manager and KMS | Preserve the deploy contract for reading and writing each scope under `vecten/<project>/<env>/` with GetSecretValue, CreateSecret and PutSecretValue. CI directly reads the Snowflake deploy user/key and reads or initializes the loader key for a Snowflake platform. Handle the six-character suffix on secret ARNs. RDS creation with managed master passwords separately needs Secrets Manager CreateSecret/TagResource and KMS DescribeKey. Check service-mediated authorization, exact AWS-managed key and secret naming on a clean sandbox. A master value read by the setup VM or laptop admin gives no reason for deploy to read every `rds!*` secret. [Deploy contract](../../../../.ai/openspec/specs/shared/deploy/spec.md) · [Snowflake calls](../../../../packages/vecten/src/vecten/deploy/snowflake.py) · [RDS managed-master prerequisites](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-secrets-manager.html) |
| Systems Manager | Read the public AL2023 AMI parameter at `/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64`. Authorize `ssm:SendCommand` on both the AWS-owned `AWS-RunShellScript` document and this environment's tagged EC2 instances in separate statements. Scope the polling action `ssm:GetCommandInvocation` by requested region where its resource must be `*`. This leaves residual access to invocation results with known IDs. The agent's message channels and the operator's StartSession are separate. [AMI lookup](../../../../terraform/aws/hosts.tf) · [Ship calls](../../../../packages/vecten/src/vecten/deploy/aws/ship.py) |
| CloudWatch Logs and STS | The ship path reads SSM invocation output directly. The module declares no log group, and the CloudWatch Logs actions found in bootstrap belong to the **host's permissions ceiling**. Leave CI log reads/writes out unless a specific workflow call demonstrates a need. Terraform checks caller identity with STS. Web-identity assumption is governed by the deploy role trust policy. [Host boundary and trust](../../../../packages/vecten/src/vecten/deploy/aws/bootstrap.py) |
| IAM | Keep the existing conditioned IAM policy as issued. Terraform can manage/pass only the named host roles and instance profiles, governed by the host boundary. Operator bootstrap owns the deploy role, trust, boundaries and proposed non-IAM policy. Verify a blank account's service-linked role prerequisites, especially RDS. If needed, have the operator create the service-specific prerequisite before apply. [IAM policy](../../../../packages/vecten/src/vecten/deploy/aws/bootstrap.py) · [RDS service-linked role](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.IAM.ServiceLinkedRoles.html) |

The provider source includes branches for configurations Vecten never renders. A Go method or a CloudTrail API event can map to several IAM actions. During implementation map the configured path to AWS's action, resource types, dependent actions and supported conditions. Document any action requiring a wildcard resource, the narrowest remaining conditions and the residual access. Carry that record with the policy tests when the provider pin changes. [AWS service authorization reference](https://docs.aws.amazon.com/service-authorization/latest/reference/reference_policies_actions-resources-contextkeys.html)
