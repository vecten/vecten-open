# Who can administer a deployed database?

**Proposed for #9.** Only the host agent that runs setup should be able to fetch a managed database's master credential on a VM. An MCP server, DAG, image build or extension service must be able to run on that same machine without gaining that ability. Host root, the operator and the reviewed code that deploys and runs the agent remain trusted. MCP still needs its provisioner and signing credentials. Those grant substantial application privileges even after this split. [Current MCP identity model](../../../../docs/mcp-identity.md#connections-credentials-and-compromise)

## What moves across the boundary

The CLI ships the setup host first. Here, the platform component runs Airflow and its DAGs, and MCP is the warehouse server. The managed Postgres state instance stores Airflow metadata or MCP application data for whichever components are present, even with an external warehouse. Terraform state is a separate object-storage record of infrastructure. Under `standard` the setup host is the MCP VM if present and the platform VM otherwise. Under `minimal` it is the one VM, `main`. Setup creates missing passwords, rereads existing values, and runs the idempotent Postgres setup SQL against private endpoints. The agent passes the master password to a short-lived `psql` helper and supplies SCRAM verifiers for the application roles. A reboot or rollback normally rebuilds run files and starts the stack without repeating database setup. [Ship order](../../../../packages/vecten/src/vecten/deploy/shipping.py) · [Agent functions `generated_names`, `run_setup`, `_start` and `ship`](../../../../packages/vecten/src/vecten/deploy/vm/apply.py)

### AWS credential delivery

Keep the host profile for SSM and agent work. Only the selected setup host gets the exact master ARNs and initialization grants. Create a separate runtime role for each active host layout, with a runtime permissions ceiling excluding RDS masters, initialization, SSM, IAM and role assumption. Have **operator bootstrap** own those runtime roles and ceilings. A runtime role trusts its environment's exact host role (account principal conditioned on its exact role ARN, so bootstrap can precede instance creation). Add `sts:AssumeRole` for that runtime role alone to both the host's inline policy and its bootstrap-managed boundary. Runtime roles sit outside the deploy role's enumerated manageable/passable host role names. [Current role and boundary rules](../../../../packages/vecten/src/vecten/deploy/aws/bootstrap.py)

The agent also uses runtime authority when resolving secret names requested by a project or extension. A root-owned host service uses the AWS Security Token Service (STS) to renew a short-lived runtime session before expiry. It atomically replaces a file in a dedicated directory on tmpfs. Mount that **directory** read-only into the Airflow and MCP consumers so replacement is visible to long-lived clients. A read-only SDK profile uses `credential_process` to read the versioned JSON response containing the access key, secret, session token and expiration. Restrict the directory to the intended container users and host root. Do not pass static credentials in Compose or send the session to proxy, build or extension containers. On boot, populate tmpfs before starting consumers. Retry renewal with a bounded delay, report the expiration without values and fail closed at expiry. Test the actual cached boto3 clients and Airflow log handler across renewal. [AWS process credential format](https://docs.aws.amazon.com/sdkref/latest/guide/feature-process-credentials.html) · [STS sessions](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html)

Set the IMDSv2 hop limit to 1 and require tokens on every host. Enforce a host firewall denial to metadata for **all** container and build bridges before Docker starts, including daemon restart and first boot. Cover both address families wherever enabled. Use a bridge with private database routing for the trusted setup helper in place of today's host network mode. Check other host-networked helpers, privileged modes, host mounts, build entitlements and the Docker socket before declaring coverage. SDK fallback or a workload's own HTTP client must hit the same boundary. [EC2 metadata options](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-instance-metadata-options.html)

### Scaleway credential delivery

Bootstrap creates one additional setup IAM application and expiring key for the environment. Its policy allows Secret Manager value access to the managed masters and exact generated names, add-version access to their generated secret records and the Airflow initialization records, and only the metadata listing needed for lookup. Keep its IAM, instance, bucket and state access empty. Narrow `host_rules` to component runtime reads, exact MCP writes and existing object grants. `SecretManagerReadOnly` may list metadata when there is no resource ID. A successful list must still confer no value access. Terraform continues to pre-create the empty secret records. [Current grant conditions](../../../../packages/vecten/src/vecten/deploy/scaleway/bootstrap.py) · [Secret records](../../../../terraform/scaleway/secrets.tf)

Keep the new key in a separate deploy-scope secret. Deliver it only to the selected setup VM via a second entry, `vecten-setup-key`, outside Terraform. Install a root-only metadata reader and block container metadata **before** delivery, including on existing servers where cloud-init no longer runs. Persist the setup key separately with mode 0600 in a root-only directory outside every build context, mount and release. Only initialization and setup select this backend. Resolve all Compose, connector and extension secret requests through the runtime backend, including on the setup host. Keep the watcher, boot, rollback, S3 signing and Airflow connection on the runtime key. Keep both copies of the stdlib Python 3.9 agent identical.

Deliver and acknowledge each key independently, binding the receipt to purpose, server ID, key ID and a fresh delivery nonce. Have the watcher authenticate the setup receipt with the newly persisted setup key (HMAC over those fields) and transport it with the runtime key. Deploy verifies it using the deploy-scope copy. This prevents another writer of the component bucket prefix from confirming setup-key receipt. Persist the verified receipt in deploy-only storage. Bootstrap matches its purpose, server ID and successor key ID against the current deployment before retiring the predecessor. Reuse the existing 30-day rotation window, retain a prior key until its own successor is confirmed, and force recreation of containers that hold the old runtime key. Delete **both** entries on success and handled failure. After cancellation, remove leftovers before apply, refresh or destroy, and refuse refresh while either entry is present. Redact both pairs from errors. [Current placement and cleanup](../../../../packages/vecten/src/vecten/deploy/scaleway/ship.py)

## Existing environments and rollback

1. **Prepare per environment.** Serialize bootstrap, apply, ship and key rotation. Record current instance IDs, layout, credential version IDs and healthy running release without reading values into a report. Upgrade the CLI, generated project Terraform/module pins, workflows and host agent protocol together. Treat a missing protocol version as legacy. On Scaleway use a compatibility ship on the existing watcher to install the new persistent watcher. On AWS use SSM to install the host service. Recheck the agent actually used by boot, rollback and replacement VMs.
2. **Stage additive resources.** Bootstrap the new principals and credentials while the legacy release can still operate. Stage the new Compose mounts and host units. Keep new AWS role-assumption permission gated until metadata isolation is active. A content-only ship encountering missing prerequisites stops before swapping releases and names the bootstrap/deploy step. Existing databases, secret names and bucket paths are reused. Inspect the Terraform plan for replacement of a host or database. Handle an unexpected replacement separately, with its data and volume recovery plan.
3. **Cut over in a maintenance window.** Pause automatic ships. Quiesce old workloads, install and verify the persistent metadata denial and block incompatible restarts. On AWS apply IMDS settings, start the refresher and verify the intended runtime role. On Scaleway reconcile admin passwords, place both keys with verified receipts, then have the operator's bootstrap remove setup and initialization grants from the **existing** host applications. Every still-valid key for each old application must lose those rights. Before the first cutover ship, install a root-owned launcher outside the releases directory. Point SSM ship commands, the Scaleway watcher, systemd boot and health-poll rollback at it. It reads the minimum supported protocol from root-owned host configuration and rejects an older bundle before executing any of its code. Only a compatible agent may update the persistent watcher. Ship the setup host first through this launcher and recreate all runtime consumers.
4. **Verify and retire.** Check a content ship, restart and the provider-specific denials below. On AWS use an operator-managed session revocation cutoff after metadata isolation is effective. A time-conditioned denial on each affected host role invalidates sessions issued before the cutoff. Keep it in force while those sessions could still be valid. Confirm a pre-cutover sandbox session is denied and the host has a newer working session for SSM and setup. [AWS session revocation](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_revoke-sessions.html) Retire superseded Scaleway keys and remove stale handoff entries and files. Once legacy access has ended, request managed master rotation from RDS on AWS. On Scaleway increment each affected instance's admin password version in tfvars and deploy so Terraform writes the new secret and deploy reconciles the database to it. Rerun setup. [RDS master rotation](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-secrets-manager.html) · [Scaleway master version handling](../../../../terraform/scaleway/secrets.tf) Keep application passwords and data. Record completion only after all hosts pass.
5. **Recover by phase.** Before the cutover, abort staging and keep the known healthy legacy release, recording it as legacy. After isolation or policy reduction, keep the boundary in place. Retry incomplete deliveries and setup idempotently, or run a known healthy *compatible* bundle through the upgraded launcher. If none exists, keep affected workloads stopped, repair via operator/deploy and ship forward. Exercise failed health polls, watcher pointer rollback, power loss and two attempts at the same step. A fresh install starts directly with the split. A restore, replacement or layout change repeats handoff for the actual new hosts before starting containers.
